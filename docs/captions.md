# Production captions

Forge captions are a deterministic derivative of an immutable timestamped transcript and, when available, the selected timeline artifact. They are generated by the durable `workflow:captions` worker before render.

## Transcript contract

The worker accepts an artifact with `kind=transcript` (or the legacy `transcription` kind) whose JSON content is either the transcript object or `{ "content": <transcript> }`.

```json
{
  "schemaVersion": "forge-transcript-v1",
  "language": "en-US",
  "source": "whisper-compatible",
  "model": "whisper-large-v3",
  "segments": [
    { "id": "seg-1", "start": 0.0, "end": 2.4, "text": "Hello world", "confidence": 0.96 }
  ]
}
```

Segments must be non-empty, ordered, non-overlapping, at least 100 ms long, and inside the timeline duration when a timeline is supplied. Invalid or missing transcripts fail the job; Forge never synthesizes transcript text.

## Outputs

A successful run creates one immutable caption version and three immutable artifacts:

- WebVTT: `text/vtt; charset=utf-8`
- SRT: `application/x-subrip; charset=utf-8`
- Machine-readable metadata: `application/json`

Each artifact records source transcript/timeline version IDs and SHA-256 metadata checksums. Caption versions/artifacts are protected by PostgreSQL immutability triggers. Re-running the same transcript + timeline pair is idempotent and reuses the deterministic caption version/artifact identities.

Text is normalized to Unicode NFC, control characters are removed, whitespace is collapsed, and cue text is bounded to protect the worker from pathological input. Caption generation is bounded by the transcript segment and input-size limits.

## Durable lifecycle

`workflow:captions` is inserted between timeline and render by the async orchestrator. Render jobs depend on the caption job and, by default, refuse to invoke the render provider unless immutable caption artifacts exist. Set `FORGE_REQUIRE_CAPTIONS=false` only for controlled legacy migrations.

Job leases, retries and idempotency remain owned by the existing Forge job queue. Caption failures are explicit non-retryable validation/provenance errors; transient database/provider infrastructure failures remain retryable through the normal job lifecycle.

## GitHub Actions

`.github/workflows/captions.yml` is a bounded, manual/dispatchable validation workflow. It checks out an immutable commit, runs the caption tests and records an explicit failure summary. It does not fetch transcript content from mutable branches and does not publish generated captions.

The workflow is intentionally independent of `akashdnb/purffle-shorts`; Shorts consumes only the existing downstream handoff contract and is not required to generate or validate long-form captions.
