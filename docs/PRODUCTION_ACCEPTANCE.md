# Production Acceptance Harness

`npm run acceptance` runs isolated synthetic episodes through the real durable workflow/control-plane and worker paths against disposable PostgreSQL and local storage. Provider-backed stages use deterministic HTTP fixtures. Forge-owned transcription/captions/QA/render/packaging/publish paths remain real; publish uses the real package/publish gate with an in-process publisher that can only return `synthetic.invalid`.

Profiles: `happy-path`, `provider-timeout-retry`, `worker-crash`, `stale-lease`, `duplicate-callback`, `missing-corrupt-artifact`, `budget-exhaustion`, `authorization-denial`, `dependency-failure`, `cancellation-race`, `partial-recovery`.

Use `FORGE_ACCEPTANCE_SEED=<seed> npm run acceptance` for replayability. Set `FORGE_ACCEPTANCE_SCENARIO=<profile>` to run one profile. Set `FORGE_ACCEPTANCE_KEEP_ARTIFACTS=true` to retain local evidence.

## Safety

No real provider credentials, external webhooks, paid generation capacity, OAuth tokens, or real publish destination are configured. The render fixture is a one-second local MP4 generated by FFmpeg. The publisher is simulated only at the external side-effect boundary.

## Failure triage

1. Preserve the JSON result and deterministic seed.
2. Re-run the same profile/seed.
3. Inspect the synthetic episode ID in `forge_jobs`, `episode_workflow_stages`, `episode_workflows`, `usage_reservations`, `usage_events`, `artifacts`, `storage_objects`, `approvals`, `qa_results`, `episode_packages`, and `publish_runs`.
4. For retries inspect attempt count and provider attempt diagnostics; for leases inspect `lease_until`; for provenance inspect version/artifact hashes and dependency edges.
5. Keep artifacts when debugging with `FORGE_ACCEPTANCE_KEEP_ARTIFACTS=true`.

A release is acceptance-ready only when `npm run check`, `npm test`, and the complete profile matrix pass against disposable PostgreSQL. Profiles that intentionally end in `FAILED`/`CANCELLED` pass only when the expected terminal outcome and invariants are satisfied.
